# RoxyDesktopPet 产品与语音架构方案

## 1. 项目定位

RoxyDesktopPet 是一个绑定固定角色“洛琪希”的 Windows 桌面宠物。项目从 ChatPet 当前工作区派生，优先打通稳定、自然的“语音输入 → 文本理解 → 带情绪的角色回复 → 语音输出”全链路。

本项目不定位为通用角色平台，也不计划在首期提供多角色、多语种或用户自行训练模型的能力。角色模型、语言、参考音频和推理参数均围绕洛琪希预先验证并固定，以换取更低的配置成本、更稳定的表现和更接近开箱即用的体验。

## 2. 首期产品边界

### 2.1 支持范围

- Windows x64 桌面应用。
- 固定角色：洛琪希。
- 固定主要输出语言；首期不提供通用多语言模型管理。
- 支持文本输入和现有语音输入链路。
- 语音输出为可选组件；用户可以只使用文字功能。
- GPT-SoVITS 本地推理首期仅支持 NVIDIA 显卡。
- 语音组件安装失败不得影响桌宠文字、主动交互和长期记忆等主体功能。
- 长期记忆继续沿用当前 Qdrant、Embedding 与观察器设计，后续再单独评估是否提供轻量降级方案。

### 2.2 首期不做

- CPU 版 GPT-SoVITS 推理。
- AMD ROCm、Intel GPU 或 macOS 推理。
- 多角色切换和角色模型市场。
- 模型训练、数据切片、降噪、ASR 标注及 UVR5。
- 要求用户自行安装 Python、Conda、CUDA Toolkit 或 Git。
- 自动安装或静默升级 NVIDIA 显卡驱动。

## 3. 目标体验

桌宠主体保持轻量安装。用户首次开启“高清角色语音”时，由应用内安装器完成环境检测、下载、校验、安装和自检。

期望流程：

1. 用户开启语音输出。
2. 应用检测 Windows 架构、NVIDIA GPU、驱动和磁盘空间。
3. 应用展示预计下载量、安装占用和最低驱动要求。
4. 用户确认后，应用从可用国内源下载固定版本组件。
5. 应用校验所有下载文件的 SHA-256，并解压到用户数据目录。
6. 应用启动独立 GPT-SoVITS 本地服务，执行 CUDA 自检和一次真实短句合成。
7. 自检成功后标记语音组件可用；以后由桌宠自动管理服务生命周期。
8. 安装失败时保留诊断日志和重试入口，桌宠自动回到无语音模式。

用户不需要打开终端、执行脚本、选择 Python 环境或理解 CUDA 版本。

## 4. 语音到语音全链路

```text
麦克风
  → 语音活动检测与录音
  → ASR
  → 用户文本
  → 对话模型与长期记忆
  → 结构化角色回复
       - spoken_text
       - emotion
       - intensity
       - delivery（可选）
  → 情绪归一化
  → 参考音频路由
  → 本地 GPT-SoVITS API
  → WAV/流式 PCM
  → 播放与桌宠动画状态
```

文本模型返回的情绪元数据不能混入实际朗读文本。推荐的内部结果结构为：

```json
{
  "spoken_text": "欢迎回来，我一直在等你。",
  "emotion": "happy",
  "intensity": 0.65,
  "delivery": "warm"
}
```

解析失败时使用原回复文本与 `neutral`，不能因为情绪字段异常而丢失整条回复。

## 5. 情绪与参考音频

首期使用有限且稳定的基础情绪集合，例如：

- `neutral`
- `happy`
- `sad`
- `angry`
- `shy`
- `surprised`
- `calm`

模型输出的其他描述应先映射到基础集合。每种情绪准备若干经过人工筛选的参考音频，并为每段音频保存准确转写、语言、强度和质量信息。

参考音频选择由桌宠负责，GPT-SoVITS 只执行推理。选择时综合考虑情绪匹配、强度、说话方式、目标文本长度和最近使用记录；找不到匹配项时逐级回退到同类情绪和 `neutral`。

所有参考音频在发布前统一完成：

- 采样率与声道规范化。
- 音量与峰值检查。
- 首尾静音清理。
- 噪声和爆音检查。
- 参考文本人工校对。
- GPT-SoVITS 实际合成回归测试。

若所选推理版本支持缓存参考特征，应在服务启动或首次使用时缓存常用情绪，减少重复编码延迟。

## 6. GPT-SoVITS 选型

首期采用 RVC-Boss/GPT-SoVITS 官方源代码和官方 `api_v2.py` 推理链路，不直接绑定第三方重构版本。

必须锁定一个经过完整回归测试的 Git commit。安装器下载该 commit 的源码快照并校验哈希，不跟踪 `main`，也不要求用户安装 Git。

本地服务仅绑定 `127.0.0.1`，由桌宠负责启动、健康检查、请求、重启和关闭。桌宠请求 `/tts` 时传入：

- 固定角色 GPT 权重。
- 固定角色 SoVITS 权重。
- 待合成文本。
- 固定文本语言。
- 情绪路由得到的参考音频路径。
- 对应的准确参考文本和语言。
- 已验证的固定推理参数。

不向普通用户暴露模型热切换、多角色管理、训练或 WebUI。

## 7. CUDA、PyTorch 与系统环境

语音安装器不安装完整 CUDA Toolkit。它在项目独立的便携 Python 环境中安装固定版本的 CUDA 版 PyTorch。PyTorch 包携带推理所需的 CUDA Runtime 组件；用户系统需要提供兼容的 NVIDIA GPU 和显卡驱动。

用户已安装的 Python、Conda 或 CUDA Toolkit 不应成为依赖，也不应被修改。所有安装和启动命令必须使用桌宠数据目录中的绝对路径。

启动语音服务时应构造受控环境，避免继承可能导致 DLL 冲突的 `PYTHONHOME`、`PYTHONPATH`、`CONDA_PREFIX`、`CUDA_HOME` 和第三方 AI 工具路径。不得删除或改写用户的全局环境变量。

NVIDIA 驱动是系统级依赖，无法随 Python 环境隔离。驱动不满足要求时，应用只给出明确诊断和官方更新指引，不自动安装驱动。

首期仅维护一个经过验证的组合，而不是自动安装多套 CUDA 变体。支持矩阵至少固定：

- Windows 版本与 x64 架构。
- 最低 NVIDIA 驱动版本。
- 已验证显卡代际。
- Python 精确版本。
- PyTorch、TorchAudio/TorchCodec 精确版本。
- PyTorch CUDA 构建版本。
- GPT-SoVITS commit。
- 基础模型版本。
- 洛琪希角色权重版本。

## 8. 固定版本清单

所有可下载组件由一个签名或随应用发布的 manifest 描述。正式发布前不得保留 `latest`、浮动依赖或未锁定的 Git 分支。

示意字段：

```json
{
  "voice_bundle_version": "待发布时确定",
  "platform": "windows-x86_64-nvidia",
  "python": {
    "version": "待验证后锁定",
    "urls": [],
    "sha256": "待确定"
  },
  "pytorch": {
    "version": "待验证后锁定",
    "cuda_build": "待验证后锁定"
  },
  "gpt_sovits": {
    "repository": "RVC-Boss/GPT-SoVITS",
    "commit": "待验证后锁定",
    "urls": [],
    "sha256": "待确定"
  },
  "pretrained_models": [],
  "character_bundle": {
    "id": "roxy",
    "version": "待确定",
    "urls": [],
    "sha256": "待确定"
  }
}
```

具体版本不能凭空填写，应先在目标显卡和目标 Windows 环境上构建、测试，再冻结到 manifest。

## 9. 下载源和安装策略

正式产品优先采用应用内安装器。PowerShell 脚本可以作为开发期验证工具和安装器底层实现，但不应要求小白用户手动运行。

每项资源至少配置一个国内稳定源，必要时提供备用源。推荐优先级：

1. 项目自有对象存储/CDN：固定角色资产、锁定后的源码快照和经过许可审查的依赖包。
2. ModelScope：适合基础模型镜像。
3. 官方 GitHub/Hugging Face/PyTorch 源：作为官方源或备用源。

下载器应支持：

- 明确显示下载量与磁盘占用。
- 超时重试和备用源切换。
- 断点续传或至少安全重试。
- SHA-256 校验。
- 下载到临时目录。
- 解压到版本目录。
- 自检成功后原子切换当前版本。
- 安装失败保留上一可用版本。
- 可定位的安装与运行日志。

不得在用户机器上从浮动 `requirements.txt` 无约束安装。发布流程应生成并验证锁定依赖，安装器只安装该版本集合。

## 10. 磁盘布局与隔离

建议将可下载语音组件放在应用数据目录，而不是 Tauri 安装目录：

```text
RoxyDesktopPetData/
└─ voice/
   ├─ manifests/
   ├─ downloads/
   ├─ versions/
   │  └─ <voice_bundle_version>/
   │     ├─ runtime/
   │     ├─ engine/
   │     ├─ pretrained/
   │     └─ character/
   ├─ active.json
   ├─ cache/
   └─ logs/
```

版本目录不可原地覆盖。新版本安装和自检成功后再更新 `active.json`，以便失败回滚。语音缓存与 Runtime 分离，可设置容量和生命周期限制。

## 11. 本地服务安全与生命周期

- 仅监听 `127.0.0.1`，不得默认监听局域网地址。
- 启动时选择空闲端口，避免与用户已有 GPT-SoVITS 服务冲突。
- 使用随机会话令牌保护本地接口。
- 服务进程只接受桌宠需要的推理请求。
- 桌宠退出时关闭服务；父进程消失后服务应能自行退出。
- 首次启动允许较长模型加载时间，但必须显示状态。
- 崩溃后最多自动重启有限次数，避免循环拉起。
- 多条回复进入统一队列，并定义打断、取消和丢弃旧回复策略。

## 12. 自检与故障降级

安装完成不以 `pip` 返回成功为准，必须完成以下验证：

1. 独立 Python 可启动且版本正确。
2. 固定依赖版本与 manifest 一致。
3. `torch.cuda.is_available()` 为真。
4. 能读取 GPU 名称并实际在 CUDA 上创建张量。
5. GPT-SoVITS 能加载基础模型和洛琪希权重。
6. 使用默认参考音频完成一次真实短句合成。
7. 输出音频可被桌宠解码和播放。

任何一步失败都应记录明确的失败阶段。语音失败时：

- 对话文本照常显示。
- 长期记忆和主动交互照常运行。
- 自动关闭本轮语音输出。
- 向用户提供重试、重新安装和查看诊断信息入口。

## 13. 长期记忆

当前长期记忆的 Qdrant Runtime、Embedding API、记忆观察与召回机制全部保留。首期不因为语音链路改造而改变记忆存储或向量模型方案。

后续可以单独评估：

- 当 Qdrant 或 Embedding 不可用时是否降级为 SQLite 全文或关键词检索。
- 是否提供本地轻量 Embedding。
- 是否允许关闭向量记忆但保留短期上下文。
- 下载型本地模型是否会与 GPT-SoVITS 争用显存、内存和磁盘。

这些决策不属于当前语音里程碑。

## 14. 建议里程碑

### M1：开发环境贯通

- 固定一个官方 GPT-SoVITS commit。
- 使用手动准备的官方环境启动 `api_v2.py`。
- 桌宠完成文本到本地 API、返回音频和播放。
- 完成固定角色默认参考音频验证。

### M2：情绪语音

- 对话模型输出结构化情绪元数据。
- 建立洛琪希情绪参考音频库。
- 完成路由、回退、队列和打断策略。
- 建立固定测试文本与人工听感基线。

### M3：固定版本安装器

- 建立 voice bundle manifest。
- 实现应用内下载、校验、解压、安装状态和日志。
- 使用独立便携 Python，安装固定 CUDA 版 PyTorch 和锁定依赖。
- 完成 NVIDIA 驱动检测与真实推理自检。

### M4：小白体验与发布验证

- 国内网络下测试主源和备用源。
- 在多代 NVIDIA 显卡与干净 Windows 环境上测试。
- 测试断网、磁盘不足、下载中断、驱动过旧和显存不足。
- 测试升级、失败回滚和卸载语音组件。
- 完成第三方许可证及模型、角色音频授权检查。

## 15. 当前架构决策摘要

1. RoxyDesktopPet 是固定洛琪希角色的桌宠，不是通用多角色平台。
2. 语音输出是可选下载组件，主体安装包保持轻量。
3. 首期只支持 Windows x64 NVIDIA GPU，不提供 CPU 推理。
4. 使用官方 GPT-SoVITS 源码及 `api_v2.py`，锁定 commit。
5. 不安装系统 CUDA Toolkit；安装独立 Python 与固定 CUDA 版 PyTorch。
6. 不依赖或修改用户已有 Python、Conda 和 CUDA Toolkit。
7. NVIDIA 驱动由用户维护，应用负责检测、诊断和提示。
8. 所有源码、依赖、基础模型和角色资产均固定版本并校验哈希。
9. 应用负责情绪理解、参考音频路由、服务生命周期与故障降级。
10. 当前长期记忆设计保持不变，降级方案后续单独讨论。
