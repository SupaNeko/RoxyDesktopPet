# 本地长期记忆设计（Rust + SQLite）

## 目标与边界

本方案借鉴 Memobase 的“事件与用户画像分离、画像按主题维护、增量合并、语义召回”思想，但不运行或打包 Memobase。它只服务单机单用户桌宠，不提供网络 API、多租户、权限、Redis 队列或 PostgreSQL 向量索引。

主对话只有读取权限。所有新增、修改和删除均由对话完成后的观察者执行；工具审计器不再暴露 `remember` 工具。记忆失败必须降级为空上下文，不能阻断聊天。

## 数据模型

- `memory_events`：不可变的观察批次账本，保存消息范围、转录、模型原始结果、处理状态和错误。用于排错和追溯。
- `memories`：当前有效画像。以 `topic/subtopic` 组织，保存内容、类型、重要度、置信度、embedding、召回次数和时间。
- `memory_revisions`：画像变更历史，记录 APPEND/UPDATE/DELETE 的新旧内容及来源事件。
- `memory_observer_state`：沿用消息游标，确保批次不会重复处理。

embedding 直接作为 little-endian `f32` BLOB 保存在 `memories`，因为本项目每条记忆只有一个模型向量，不需要 Memobase/PostgreSQL 的独立向量表。

## 观察与合并

观察者一次向 LLM 提交当前画像（最多 200 条）和待处理对话，要求输出 JSON 动作：

- `APPEND`：新增长期事实。
- `UPDATE`：冲突、修正、补充或去重，必须引用现有 `target_id` 并返回完整新内容。
- `DELETE`：用户明确否定旧事实，必须引用现有 `target_id`。
- `ABORT`：重复、临时、无价值、敏感或低置信信息。

这对应 Memobase YOLO merge 的 APPEND/UPDATE/ABORT；本地版增加 DELETE，以明确表达撤回而非把否定句继续合并进画像。动作在单个 SQLite 事务中应用，同时写入 revision。只有 APPEND/UPDATE 会生成新 embedding。

## 与 Memobase 因数据库不同产生的处理

1. **向量检索**：不用 pgvector。最多加载 5000 条活跃画像，在 Rust 中计算余弦相似度。单用户规模下复杂度和内存可控，也消除了独立数据库进程。
2. **并发与任务队列**：不用 Redis。`ConversationState` 串行化观察任务，SQLite 事务保证画像和修订一致。观察失败保留 failed event 且不推进游标，下一次可重试。
3. **候选合并**：Memobase 可依赖数据库分组和检索；本地版把最多 200 条当前画像交给观察模型。超过该规模后应增加“按 topic + embedding 预筛选”，当前单用户桌宠预计不会成为瓶颈。
4. **事件搜索**：当前不把原始事件参与主对话召回，只召回整理后的画像。事件表主要用于审计，避免短期对话污染长期上下文。
5. **模型变更**：每条向量记录模型和维度。召回时维度不一致的向量自动得零分；后续可添加后台重嵌入，不影响文本画像。
6. **迁移**：项目开发阶段不迁移 Qdrant/Memobase 数据。SQLite 建表仍采用幂等迁移，方便开发安装覆盖。

## 召回排序

先生成查询 embedding，再对活跃画像计算：

```text
score = 0.62 * cosine_similarity
      + 0.18 * 中文字符/二元词重合度
      + 0.10 * importance
      + 0.05 * confidence
      + 0.03 * 180 天指数时间衰减
      + 0.02 * 对数召回强化
```

语义相似度至少 0.28 或词面重合至少 0.18 才入选，最多返回 8 条。权重是面向桌宠小规模画像的初始值，需要用真实对话回放校准，不视为 Memobase 原权重的复制。

## 一致性与降级

- 模型响应必须通过强类型 JSON 解析；非法动作不会写入数据库。
- APPEND/UPDATE 的 embedding 成功后才进入应用事务，避免产生半成品画像。
- UPDATE/DELETE 引用不存在或已删除 ID 时跳过，不会误改其他画像。
- 主对话 embedding 或 SQLite 查询失败时记录日志并使用空记忆继续回复。
- 数据库写入使用事务；事件账本保留原始模型输出，便于复现误合并。

## 后续增强

- 对超过 200 条画像的观察合并增加候选预筛选。
- 增加可视化的画像查看、手动删除和修订审计页。
- 增加定期重嵌入、重复画像压缩及 prompt 回放评测集。
- 对 observer LLM 超时增加有上限的指数退避，避免持续故障时频繁调用。

## 许可证说明

本实现复用了 Memobase 的架构思想和动作语义，并重新编写了适合本项目的中文提示词与 Rust 代码；未复制其服务实现。若后续直接复制 Memobase 提示词或源码，应按其许可证保留声明。
