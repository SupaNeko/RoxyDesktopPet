# ChatPet 需求规格说明书

> 文档状态：初稿基线  
> 目标平台：Windows 10/11  
> 数据策略：本地优先，模型能力通过 API 接入  
> 更新日期：2026-08-21

## 1. 产品概述

ChatPet 是一个常驻 Windows 桌面的陪伴型桌宠。它以可配置的人格与用户进行文字或语音对话，维护本地长期记忆和待办事项，并通过可靠调度、低频主动消息形成持续陪伴。

产品不承担通用生产力 Agent 职责，不提供文件读写、Shell、浏览器控制或任意程序操作能力。第一阶段使用静态 PNG/GIF 作为桌宠形象，Live2D 不属于核心范围。

## 2. 产品目标

1. 提供低打扰、可随时关闭的桌面陪伴体验。
2. 支持文字输入与“本地持续监听、按句调用 ASR API”的语音输入。
3. 通过外部 LLM API 维持稳定人物性格，并处理对话、Todo 工具调用、提醒措辞和主动消息。
4. 使用外部 Embedding API 与本地 Qdrant 建立可观察、可管理的长期记忆。
5. 将 AgentStage 的“中文回复 → 人设化日语翻译 → 独立 VITS EXE → WAV 播放”作为可选语音输出能力复用。
6. 所有业务数据保存在本机；除明确提交给模型 API 的内容外，不上传数据库、录音文件或运行日志。

## 3. 非目标

- 不提供读写用户文件、执行命令、控制应用或代替用户操作电脑的能力。
- 不截屏，不读取窗口正文、键盘输入、剪贴板、浏览器历史或浏览器 URL。
- 不要求 Live2D、3D 模型、摄像头或视觉模型。
- 不在本地运行 LLM、ASR 或 Embedding 大模型。
- 不做多用户、跨设备同步、云端数据库或移动端。
- 第一阶段不承诺识别“当前正在使用的应用”；该能力为低优先级可选项。

## 4. 用户体验与核心流程

### 4.1 文本对话

1. 用户在桌宠输入框输入中文。
2. 系统检索与输入相关的长期记忆，组装人格上下文。
3. 调用 LLM API。
4. 中文回复流式或完整显示在桌面气泡/聊天面板。
5. 仅当用户开启语音输出且检测到可用的 VITS EXE 时，后台才对中文回复进行人设化日语翻译并调用 VITS。
6. VITS 完成后播放日语音频；翻译文本不替换界面上的中文回复。未提供 VITS EXE 时直接结束语音派生链路，不调用翻译模型，不显示消息级错误，也不影响中文回复。

### 4.2 持续语音输入

1. 用户主动打开“持续语音输入”开关。
2. 客户端只打开用户选择的麦克风捕获端点，不使用系统音频 Loopback。
3. 本地 Silero VAD 持续处理小块 PCM 音频，不调用外部 API。
4. 容错状态机确认说话开始和句末后，形成一个内存音频片段。
5. 仅将完成的有效片段发送给 ASR API。
6. ASR 返回中文文本；文本显示为用户输入并触发一次标准对话调用。
7. 空结果、低置信度结果、纯标点、重复结果和过短片段不得触发 LLM。

### 4.3 Todo 创建与可靠提醒

1. 用户用文字或语音表达提醒意图。
2. LLM 通过受限工具 `create_todo`、`update_todo`、`complete_todo`、`delete_todo` 或 `list_todos` 操作结构化 Todo。
3. 对时间、时区或复现规则存在实质歧义时，桌宠必须追问，不能猜测后直接创建。
4. Todo 写入本地 SQLite；可靠调度器不依赖 LLM 存活。
5. 到点后调度器创建 `reminder_due` 事件并调用 LLM，要求角色按人格提醒指定事项。
6. 中文提醒立即显示；随后走日语翻译和 VITS 链路。
7. 若 LLM 调用失败，必须显示确定性降级提醒；事件保留可重试状态，不得静默丢失。

### 4.4 偶发主动消息

1. 用户可独立启用或关闭主动消息。
2. 用户可配置最短间隔、最长间隔、每日上限与安静时段。
3. 本地调度器决定是否产生 `companion_tick`；模型只决定“说什么”，不决定可靠任务是否触发。
4. 正在处理用户输入、正在生成回复、处于安静时段或达到每日上限时应跳过。
5. 主动消息允许因离线、限流或应用退出而丢弃，不应在恢复后批量补发。

## 5. 功能需求

### 5.1 桌面呈现

- FR-UI-01：提供透明、无边框、可拖动、可置顶的桌宠窗口。
- FR-UI-02：支持静态 PNG，建议同时支持透明 GIF；素材由用户本地选择。
- FR-UI-03：提供系统托盘入口、显示/隐藏、退出、麦克风开关和静音开关。
- FR-UI-04：提供文本输入框、对话气泡和可展开的历史面板。
- FR-UI-05：提供明确状态：空闲、监听、检测到说话、转写、思考、合成、播放、错误。
- FR-UI-06：桌宠隐藏时，可靠提醒仍可通过 Windows 通知和托盘提示到达。

### 5.2 人格与模型配置

- FR-CHAR-01：支持配置名称、称呼、详细人设、语言风格、关系设定、主动消息偏好和头像。
- FR-CHAR-02：人格作为版本化配置保存在本地。
- FR-CHAR-03：对话、提醒、主动消息和 TTS 翻译必须使用同一角色身份；各场景允许使用不同的任务提示模板。
- FR-MODEL-01：支持 OpenAI-compatible LLM API 配置：Base URL、模型名、API Key、温度和超时。
- FR-MODEL-02：ASR、Embedding 和翻译模型配置相互独立。
- FR-MODEL-03：API Key 必须使用 Windows DPAPI 或等价 OS 凭据机制加密，不得进入前端状态、日志或明文数据库字段。

### 5.3 麦克风、VAD 与 ASR

- FR-AUDIO-01：只枚举和打开 Windows 音频“捕获端点”；禁止启用 WASAPI Loopback 或录制渲染端点。
- FR-AUDIO-02：用户可选择输入设备；设备失效时停止监听并显示错误，不可静默切换到未知设备。
- FR-AUDIO-03：默认采集格式为 16 kHz、单声道、16-bit PCM；必要时从设备原始格式本地重采样。
- FR-AUDIO-04：VAD 使用本地 Silero VAD ONNX，不将连续原始音频上传云端。
- FR-AUDIO-05：语句端点检测至少包含：预滚动缓冲、开始阈值、结束静音、最短语音、最大语句长度、滞回阈值和冷却时间。
- FR-AUDIO-06：建议默认值：预滚动 300 ms；连续语音开始 180 ms；句末静音 900 ms；最短语句 400 ms；最长 30 s；冷却 300 ms。所有值应可在高级设置调整。
- FR-AUDIO-07：ASR 只接收完成语句；默认语言提示为中文。
- FR-AUDIO-08：ASR 前后均做容错过滤：有效语音占比、音量下限、文本清洗、重复窗口和最小有效字符数。
- FR-AUDIO-09：应用播放 VITS 音频使用 Windows 渲染端点，与麦克风捕获会话分离；应用不得把 PCM 输出直接回送到识别管线。
- FR-AUDIO-10：本项目不处理扬声器声音经空气被物理麦克风再次拾取的回声场景；第一阶段不实现 AEC 和插话打断。
- FR-AUDIO-11：原始音频默认只保存在内存，ASR 完成或失败后释放；调试录音必须由用户单独开启并明确标记。

### 5.4 对话编排

- FR-CHAT-01：所有对话触发统一进入编排器：`user_text`、`user_voice`、`reminder_due`、`companion_tick`。
- FR-CHAT-02：同一角色的 LLM 调用串行化，防止回复、提醒和主动消息互相覆盖。
- FR-CHAT-03：用户输入优先级高于主动消息；可靠提醒到期后进入可靠队列，不得被普通主动消息覆盖。
- FR-CHAT-04：仅暴露 Todo 和记忆管理所需的受限工具，不暴露文件、Shell、HTTP 任意请求或应用控制工具。
- FR-CHAT-05：模型输出、工具参数和时间字段必须通过结构化校验。
- FR-CHAT-06：API 超时、429、5xx 支持有限指数退避；用户请求与可靠提醒应给出可见失败状态。

### 5.5 Todo 与调度

- FR-TODO-01：支持一次性提醒；后续版本支持每日、工作日和固定间隔复现。
- FR-TODO-02：每条 Todo 至少包含标题、到期时间、时区、状态、复现规则、创建来源和最后提醒状态。
- FR-TODO-03：调度状态必须持久化；应用重启后重新计算未完成任务。
- FR-TODO-04：启动时对错过的提醒执行恢复策略：默认仅补发最近 24 小时内未提醒的可靠任务，并标记为迟到提醒。
- FR-TODO-05：同一触发实例具有幂等键，应用崩溃或重试不得产生无限重复提醒。
- FR-TODO-06：提醒模型调用输入必须包含角色人设、明确任务、原定时间、当前时间及是否迟到。

### 5.6 长期记忆与 Qdrant

- FR-MEM-01：使用本地 Qdrant 存储向量和 payload，Embedding 由外部 API 生成。
- FR-MEM-02：SQLite 保存记忆元数据的业务事实源；Qdrant 用于语义检索，不承担 Todo 或消息事实源职责。
- FR-MEM-03：对话结束后由 LLM 判断并提取候选长期记忆，不直接把每轮原始对话全部写入向量库。
- FR-MEM-04：记忆类型至少包括用户事实、偏好、习惯、关系、经历和角色共同经历。
- FR-MEM-05：写入前执行规范化、近邻去重与更新判断；冲突记忆不得简单并存为同等可信事实。
- FR-MEM-06：检索支持角色 ID、记忆类型、有效状态和时间范围过滤，再执行 Top-K 相似度召回。
- FR-MEM-07：提供记忆查看、编辑、停用、删除和重新向量化功能。
- FR-MEM-08：Embedding 模型或维度变化时创建新 collection 或执行显式重建，禁止向同一 collection 混写不同维度向量。
- FR-MEM-09：Qdrant 不可用时对话仍可降级运行，但界面必须显示“长期记忆暂不可用”。

### 5.7 翻译与 VITS

- FR-VOICE-01：复用 AgentStage 的 `vits_runtime.exe`，作为持久子进程运行。
- FR-VOICE-01A：VITS 语音输出属于可选功能；应用启动、文字/语音输入、对话、记忆、Todo 和提醒均不得依赖 VITS Runtime 存在。
- FR-VOICE-02：主程序与 VITS 通过 UTF-8 stdin/stdout 单行 JSON 请求/响应通信；日志仅写 stderr。
- FR-VOICE-03：VITS 启动就绪信号、请求字段和响应字段与 AgentStage 现有协议兼容。
- FR-VOICE-04：中文回复先显示，再异步执行翻译与合成；VITS 失败不得阻塞或撤销文本回复。
- FR-VOICE-05：翻译为独立 LLM 调用，不写入会话历史；注入角色人设、关系与本次相关记忆。
- FR-VOICE-06：目标语言固定支持日语 `ja`；翻译必须保持角色口吻，并尽量保持原标点与句子边界。
- FR-VOICE-07：按消息 ID 缓存 WAV；重复播放优先命中本地缓存。
- FR-VOICE-08：播放队列按回复顺序执行；过期主动消息的音频可取消，可靠提醒音频不可静默丢弃。
- FR-VOICE-09：语音派生链路的前置条件为“用户开启语音输出且 VITS EXE 可用”。条件不满足时跳过翻译、VITS 与播放，中文文本仍视为正常交付。
- FR-VOICE-10：用户开启语音输出但未检测到 EXE 时，设置页显示“VITS 未配置，当前仅显示文本”的非阻断状态；不得为每条消息重复弹错。

### 5.8 低优先级 Windows 事件

- FR-EVENT-01：该模块默认关闭，用户逐项授权。
- FR-EVENT-02：第一阶段候选事件仅包括锁屏/解锁、用户空闲/恢复、电源/电量和系统媒体播放状态。
- FR-EVENT-03：音乐信息使用 Windows Global System Media Transport Controls Session API；支持时可读取播放器、播放/暂停、标题和艺术家。
- FR-EVENT-04：歌曲元数据授权与“仅识别正在播放音乐”授权分离。
- FR-EVENT-05：事件先进入本地状态缓存，不因每次切歌直接调用 LLM；仅在下一次对话或主动消息中按策略注入摘要。
- FR-EVENT-06：不得读取系统音频数据本身。

## 6. 数据与隐私

- 本地数据：SQLite、Qdrant 存储、角色素材、VITS 模型、WAV 缓存、配置和日志。
- 外发数据：用户明确提交的文本、被 VAD 切出的语音片段、Embedding 输入文本、翻译输入文本，以及调用所需的人设/召回记忆。
- 默认不保存原始麦克风录音。
- 设置页必须展示每类 API 可能接收的数据。
- 支持删除单条记忆、清空对话、清空音频缓存和清空全部本地数据。
- 日志不得记录 API Key；生产默认不记录完整音频或完整 Prompt，可启用脱敏诊断模式。

## 7. 非功能需求

- NFR-01：Windows 10 22H2、Windows 11 为目标环境，x64 优先。
- NFR-02：空闲常驻时 CPU 应保持低占用；VAD 使用单独工作线程，不阻塞 UI。
- NFR-03：麦克风开关关闭后应在 1 秒内释放捕获设备。
- NFR-04：VAD 检测到句末至 ASR 请求发出，目标延迟低于 300 ms（不含网络）。
- NFR-05：LLM 中文文本一旦可用立即展示，不等待翻译和 VITS。
- NFR-06：SQLite 使用 WAL；写入 Todo、提醒实例和消息时保证事务一致性。
- NFR-07：外部 API、Qdrant 和 VITS 任一组件失败不得导致主进程崩溃。
- NFR-08：应用重启后恢复未完成 Todo、提醒投递状态、角色配置和记忆索引状态。

## 8. MVP 范围与验收

### 8.1 MVP 必须包含

- Windows 透明静态桌宠、托盘与聊天面板。
- 文本对话和人格配置。
- Silero VAD 本地持续监听、句级 ASR API。
- SQLite Todo、一次性可靠提醒、提醒触发 LLM。
- 可配置随机主动消息与安静时段。
- 外部 Embedding API + 本地 Qdrant 的写入、检索、删除。
- AgentStage 兼容的人设日语翻译和 VITS EXE 调用。
- 麦克风输入与音频输出数字链路隔离。

### 8.2 后续范围

- Windows 媒体/空闲/锁屏事件。
- 周期 Todo、贪睡和复杂自然语言日期。
- GIF 状态动画或 Live2D。
- AEC、播放中插话、唤醒词和说话人识别。

### 8.3 核心验收场景

1. 麦克风开启 30 分钟且无人说话，不产生 ASR 或 LLM 调用。
2. 用户说完一句中文后只产生一次 ASR 和一次对话调用，不因短暂停顿无限拆句。
3. 应用播放 VITS 时，PCM 输出不会进入 ASR 输入管线；系统播放音频也不会通过 Loopback 被采集。
4. “晚上九点提醒我吃药”成功创建本地 Todo，到点必定产生提醒模型调用；模型失败时显示降级提醒。
5. 中文回复先显示，日语音频后到达；翻译失败不影响中文回复；缺少 VITS EXE 时不调用翻译并正常保持纯文本模式。
6. 重启应用后 Todo、提醒状态、角色和记忆仍存在。
7. Qdrant 停止后仍可聊天；恢复后可继续检索。
8. 删除一条记忆后，该记忆不再被检索或注入模型。

## 9. 已确认决策与待定项

### 已确认

- Windows only。
- 静态桌宠优先，Live2D 低优先级。
- Qdrant 本地运行。
- Silero VAD 本地运行并配合容错状态机。
- LLM、ASR、Embedding 通过 API 接入。
- 不截屏、不做文件工具。
- 可靠提醒必须调用模型生成角色化提醒。
- 中文显示；人设化日语翻译后交给 VITS。
- 复用 AgentStage 的独立 VITS EXE 服务。
- VITS 为可选能力，缺少 EXE 时自动跳过翻译与语音输出。

### 实现前待确认

- 默认 LLM/ASR/Embedding API 供应商与协议差异。
- Qdrant 采用随应用管理的本地进程，还是要求用户安装 Docker。
- ChatPet 是否直接复用 AgentStage 的 Tauri/Svelte/Rust 技术栈。
- VITS Runtime、模型文件和许可证是否允许随 ChatPet 分发，还是仅由用户自行放置。
- 对话 LLM 是否要求流式输出；若流式，语音按整条还是按分句合成。
